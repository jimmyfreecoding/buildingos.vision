# 边缘端存储优化与 AI 日报生成策略

本文档描述了 `BuildingOS Vision` 系统针对边缘端（Jetson Orin Nano）有限存储空间的自动收敛策略，以及基于 Gemma 4 E2B 的每日 AI 检测摘要生成机制。

## 1. 存储优化策略 (Storage Optimization)

由于系统开启了高频的人员占用检测和截图功能，每日产生的原始数据可能达到数 GB。系统通过 `daily_cleanup.py` 脚本实现数据的自动收敛。

### 1.1 WebP 极致压缩
- **格式转换**：将原始的 `.jpg` 图片统一转换为 `.webp` 格式。
- **分辨率收敛**：自动将图片等比例缩放至最大宽度 **800px**。
- **质量压缩**：采用 **50%** 的 WebP 质量设置。
- **收益**：单张图片体积可从 ~1MB 降低至 **30KB~50KB**，整体存储空间占用降低 **90% 以上**。

### 1.2 数据一致性保障
- **JSON 同步更新**：在图片转换完成后，脚本会自动扫描并修改同目录下的 `.json` 文件，将图片引用后缀从 `.jpg` 替换为 `.webp`，确保前端界面能正常显示。
- **幂等性检查**：脚本会识别已处理的文件，避免对同一张图进行二次压缩导致质量过度下降。

### 1.3 运行安全
- **5分钟安全窗口**：脚本仅处理最后修改时间在 **5分钟前** 的文件。这确保了 AI Engine 已彻底完成该文件的写入并关闭，有效避免读写冲突。

## 2. AI 深度日报 (AI Daily Summary)

系统不仅进行物理层面的存储压缩，还会对当天的检测数据进行深度挖掘，并利用本地运行的 Gemma 4 E2B 模型生成自然语言报告。

### 2.1 统计维度
脚本会解析 `decision_chain`（决策链），统计以下核心指标：
- **一级判定 (Level 1)**：Detector (YOLO) 直接确认有人且无需复核的次数。
- **二级复核 (Level 2)**：触发 Gemma 复核的总次数，以及复核后的“确认有人”与“排除误报”比例。
- **时间段分析 (Timeline)**：
    - 自动识别每个区域的“有人”和“无人”连续时间段。
    - 计算每个区域的总“有人时长”和“无人时长”。
- **异常事件**：如吸烟告警等特殊事件的汇总。

### 2.2 Gemma 报告生成
- **数据喂入**：将上述统计数据（含时间段）以 JSON 格式喂给本地 Gemma 模型。
- **报告内容**：
    - 采用 **Markdown** 格式生成。
    - 总结整体办公区占用效率。
    - **分区域详细列出有人/无人的具体时间段及总时长。**
    - 分析 Detector 与 Gemma 的协同工作状态。
    - 列出二级复核发生的具体时间点和判定理由。
- **展示**：Web 端支持 Markdown 渲染，提供精美的图文分析报告。

## 3. 使用方法

### 手动触发
在宿主机执行以下指令：
```bash
python3 ~/buildingos.vision/ai_engine/src/daily_cleanup.py [YYYY-MM-DD]
```
如果不指定日期，默认处理当天数据。

### 定时任务 (建议)
建议通过 `crontab` 设置在每日凌晨（如 03:00）运行：
```bash
0 3 * * * /usr/bin/python3 /home/buildingos/buildingos.vision/ai_engine/src/daily_cleanup.py >> /home/buildingos/cleanup.log 2>&1
```
