# 办公场景吸烟检测：从 YOLO 到 RF-DETR + ROI 局部强化的演进方案

## 1. 现状痛点分析 (Why it fails?)

在写字楼过道、办公室等实际监控场景中，传统的 YOLO 全图检测方案往往面临以下挑战：

### 1.1 分辨率稀释 (Small Target Problem)
*   **现象**：摄像头通常安装在天花板（3-4米高），俯拍视野广。
*   **数据**：在 1080P 画面中，人体可能只占 2-5% 的面积，而香烟/烟支仅占 **几个像素点**。
*   **后果**：YOLO 的卷积下采样过程会将细微的香烟特征视为“噪声”抹除，导致 mAP 很高但实测全漏。

### 1.2 环境与姿态鸿沟 (Domain Gap)
*   **视角**：开源数据集多为平视/特写，而实景是**高俯拍**，只能看到头顶、肩膀和部分手部动作。
*   **干扰**：摸鼻子、看手机、整理口罩等动作在低分辨率下与吸烟极其相似。

---

## 2. 演进方案：三级联动“漏斗式”检测架构

不再依赖单一模型跑全图，而是利用 Jetson 的算力优势实现精细化分层处理。

### 2.1 第一级：人员感知与追踪 (RF-DETR Presence)
*   **模型**：使用现有的 **RF-DETR (ZF)** 模型（对俯视视角和人体轮廓更鲁棒）。
*   **任务**：锁定画面中的行人，输出 **BBox (包围框)**。
*   **目的**：过滤 90% 的无效背景，实现“有人才检测，无人则休眠”。

### 2.2 第二级：ROI 局部高精增强 (Crop & Zoom + RF-DETR Specialist)
*   **核心逻辑**：
    1.  获取第一级输出的人员坐标。
    2.  在原始高清流中，截取以人为中心、包含上半身的 **640x640 局部高清图 (ROI)**。
    3.  将局部图送入 **RF-DETR 吸烟专用模型**。
*   **优势**：
    *   **像素级放大**：目标特征在模型眼中的比例提升了 **5-10 倍**。
    *   **架构优越性**：Transformer 的注意力机制（Attention）能更好地学习“人脸角度-手部位置-白点特征”之间的语义关联。

### 2.3 第三级：Gemma 语义仲裁 (Gemma 4 Verification)
*   **触发条件**：第二级模型给出中等置信度（如 0.3 - 0.5）的“疑似”信号时。
*   **逻辑**：将 ROI 截图发给本地运行的 **Gemma**。
*   **Prompt 示例**：`图中人物在走廊，请仔细观察其手部是否持有香烟，并结合嘴部动作判断其是否在吸烟？`
*   **目的**：利用大语言模型的常识推理，排除摸鼻子、整理领带等引起的误报。

---

## 3. 数据闭环与微调策略 (Site-Specific Loop)

### 3.1 样本收集
*   **正样本**：在实际摄像头下，由员工在不同角度（正对、背对、侧对）、不同光照下模拟吸烟。
*   **负样本**：大量收集在过道看手机、喝水、揉眼睛、带口罩的“易混淆动作”。

### 3.2 模型转换
*   将现有的 YOLO 格式数据集（`.txt` 标注）转换为 COCO 格式（`.json`）。
*   利用项目内置的训练脚本对 **RF-DETR** 进行微调，生成专属于本场景的 `.engine` 权重。

## 4. 方案预期收益

| 维度 | 预期提升 | 说明 |
| :--- | :--- | :--- |
| **检测率 (Recall)** | **提升 200%+** | ROI 放大彻底解决了“看不见”的问题 |
| **误报率 (Precision)** | **降低 80%+** | Gemma 复核与负样本训练排除了“看错”的问题 |
| **启动性能** | **极速响应** | 纯 TensorRT 架构，不加载 Torch，秒级启动 |
| **运行稳定性** | **显存锁定** | 静态显存分配，不再受 CUDA 库版本冲突困扰 |

## 5. 下一步行动路线

1.  **数据转换**：运行 `yolo_to_coco.py` 转换现有数据集。
2.  **模型训练**：基于 RF-DETR 架构训练吸烟专用模型。
3.  **逻辑集成**：在 `main.py` 中实现 `crop_person_roi` 逻辑，并将检测结果存入 `daily_summary.json`。

## 6. 内存消耗预估（Memory Footprint Analysis）

在 Jetson Orin Nano 8GB 上，切换到“全线 RF-DETR (No-Torch)”架构后的内存收益非常显著。

### 6.1 现有方案（YOLO + Torch）内存开销
*   **Torch 框架基础占用**：~600MB - 800MB（加载 `torch` 核心库及 CUDA 上下文）。
*   **YOLOv8s 模型权重**：~150MB（含 TensorRT 运行时显存）。
*   **多模型切换抖动**：~200MB（动态推理产生的临时缓冲区）。
*   **总计预估**：**950MB - 1150MB**。

### 6.2 新方案（纯 RF-DETR + No-Torch）内存开销
*   **Torch 框架基础占用**：**0MB**（彻底卸载 `torch`，仅使用轻量级 `pycuda`）。
*   **RF-DETR Presence 模型**：~120MB（静态分配，TensorRT 优化）。
*   **RF-DETR Smoking (ROI) 模型**：~120MB（静态分配）。
*   **局部图像缓冲区**：~50MB（用于存储 640x640 的 ROI 截图）。
*   **总计预估**：**290MB - 350MB**。

### 6.3 结论与收益
*   **内存节省**：相比旧方案，新方案可节省约 **700MB - 800MB** 的宝贵显存。
*   **稳定性**：由于去掉了 `torch` 的动态内存管理，显存占用变为“静态直线”，极大降低了因 OOM（内存溢出）导致系统重启的风险。
*   **空间腾挪**：节省出的这部分显存，正好可以完整容纳 **Gemma 4** 模型（约需 4GB-5GB）的运行需求，使得“边缘侧大模型复核”成为可能。
